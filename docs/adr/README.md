# Architecture decision records

Each ADR records one decision in the Nygard format (ADR 1). An ADR is never rewritten to say
something different: a later change is added as an **amendment** at the end of the same file, or
as a new ADR that supersedes it. Read an ADR together with its amendments; where they disagree,
the later amendment wins.

## Notes on residuals recorded in ADRs

- ADR 15, amendment 2, left `CaseSession.publish` outside the entity lock. It is now under
  `withEntityLock` (`src/core/session.ts`), as are `renameEntity` and `updateEntity`. The checks
  in `changeEntity` (people.ts) are still not inside `updateEntity`/`renameEntity` themselves;
  `changeEntity` is their only caller.
- ADR 21 says who's who has no person→address link, so the export warning uses a label rule. ADR
  15 amendment 3 has since added `relatedTo`, but `src/core/export/safety.ts` does not use it yet
  (see `docs/PLAN.md`, known limitations).
